# CHUNITHM Launcher UI 设计规范

本文档是 `ui/` 静态前端的视觉和交互规范。新增或修改组件时，以现有组件的结构、状态和主题规则为准；不要为单个页面创建一套孤立的颜色或动效。

## 1. 运行范围

- 当前运行前端是 `ui/index.html`、`ui/app.js`、`ui/styles.css`。
- `ui-vue/` 是暂停中的迁移目录，不属于当前发布路径。
- 发布时由 .NET 项目把 `ui/` 原样放入 `app/ui/`。

## 2. 主题色板

### 浅色模式

| 用途 | 色值 |
| --- | --- |
| 工作区背景 | `#e9e7ee` |
| 卡片、面板、普通控件表面 | `#f5f2f9` |
| 浅色次级按钮/分隔区域 | `#e9e7ee` |
| 主文字 | `#332f3c` |
| 次文字 | `#7d7787` |
| 主色 | `#fdd500` |

### 深色模式

| 用途 | 色值 |
| --- | --- |
| 工作区背景 | `#222222` |
| 卡片、面板表面 | `#333333` |
| 输入框、下拉触发器、下拉面板 | `#454545` |
| 次级按钮（GitHub 主页、检查更新、捐赠等） | `#454545` |
| 次级控件悬停 | `#4d4d4d` |
| 主文字 | `#f2f2f2` |
| 次文字 | `#c2c2c2` |
| 主色 | `#fdd500` |

页面背景、卡片表面和表单控件必须分层。侧边栏按钮可以与侧边栏背景相同，不能因为表单控件改为 `#454545` 而同步改变侧边栏按钮。

## 3. 通用组件

### 按钮

- 使用 `.app-button`，主操作使用 `.primary`。
- 普通按钮使用主题表面色，悬停只提升亮度，不改变布局。
- 主按钮使用 `var(--accent)`，文字使用深色高对比色。
- 按钮状态通过颜色、文字和形状共同表达，不能只依赖颜色。

### 输入框

- 使用 `.field-shell` 包裹输入框，以复用焦点扩散环。
- 高度 `44px`、圆角 `12px`、左右内边距 `13px`。
- 浅色输入框使用 `#f5f2f9`；深色输入框使用 `#454545`。
- 聚焦时使用 `var(--focus-border)` 和共享焦点动画；不要为单个输入框创建不同的焦点样式。
- 只读字段保留键盘可访问性，但不能修改值。

### 下拉选择

- 使用 `.display-picker`、`.display-picker-trigger` 和固定定位的 `.display-picker-panel`。
- 下拉触发器和面板必须跟随主题切换，深色模式使用 `#454545`。
- 面板关闭动画完成前保留定位变量，避免回到左上角闪烁。
- 下拉选项使用统一的悬停、聚焦和选中状态。

### 复选框

- 所有复选框使用 `<label class="checkbox"><input type="checkbox"><span></span>文字</label>` 结构。
- 未选中：16px 空心圆，透明填充，主题色细边框。
- 选中：主题色实心圆，**不显示额外的半透明外圈**。
- 键盘聚焦必须显示额外焦点轮廓。
- 复选框命中区域包含圆形控件和文字标签，不应依赖颜色单独表达状态。

### 卡片

- 复用 `.app-panel`、`.content-card`、`.metric-card`、`.friend-row` 等现有卡片类。
- 默认使用无边框、圆角和轻量层次；不要给同一层级的卡片混入新的阴影体系。
- 颜色变化使用统一的 `350ms ease` 过渡。

## 4. 活动轮播

- 首页 `#homeEventImage` 与活动页 `#activityEventImage` 必须保持相同的尺寸、箭头、指示点和切换逻辑。
- 图片使用双图轨道做水平平移，使用非线性曲线，不使用淡入淡出。
- 动画持续时间固定为 `520ms`；动画未完成时忽略新的翻页点击，不排队。
- 活动文案单独淡出、更新、淡入；文案卡片背景、边框、滚动区域和详情按钮保持静止。

## 5. 页面与导航

- 侧边栏宽度和导航按钮尺寸沿用现有 `.launcher-rail`、`.rail-link`。
- 导航图标从 `ui/assets` 加载：带 `(1)` 的文件用于浅色模式，不带括号的文件用于深色模式。
- 查分导航使用文字 `Rating`；Aime 使用 `aime-rail.png`。
- 演示账户头像使用 `迪拉熊头像.png`。
- 全局禁止选择页面文字，输入框和可编辑元素必须保留文本选择能力。

## 6. 主题切换和无障碍

- 主题切换统一使用 `350ms ease` 的背景、文字、边框和阴影过渡。
- 必须覆盖浅色、深色、悬停、聚焦、选中、禁用状态。
- 保留 `prefers-reduced-motion`，减少动画时长而不破坏布局。
- 新增固定定位面板时，必须同时提供浅色和深色选择器，不能假设 `.page.dark` 会覆盖页面外的元素。

## 7. 国际化

- 所有用户可见文案、占位符、按钮标签、状态提示和无障碍标签必须从 `ui/app.js` 的 `UI_TEXT` 目录读取，禁止在新逻辑中直接拼接单语言文案。
- 设置页语言选项固定为：`跟随系统`、`简体中文`、`English`、`日本語`、`한국어`、`Français`、`Español`、`Deutsch`。默认值为跟随系统；系统语言以 WebView 浏览器语言为准，未覆盖的语言回退到简体中文。
- 语言偏好使用 `chunithm-language` 本地缓存，并随 `save-settings` 写入宿主配置；宿主通过 `init.language` 回传，保证重启后保持一致。
- 切换语言时必须同步更新 `html[lang]`、`document.title`、静态页面文案、动态轮播/资讯、状态提示、placeholder、`aria-label` 和下拉选项。
- 新增翻译时中英文键必须成对出现；数字、曲名、路径、URL 和版本号等数据保持原值，只翻译外围说明文字。

## 8. 修改前检查清单

1. 先检查现有 DOM 祖先和最终 CSS 层叠。
2. 优先复用现有组件类和主题变量。
3. 同时检查浅色、深色、聚焦、悬停和选中状态。
4. 运行 `node --check ui/app.js` 和 `git diff --check`。
5. UI 修改完成后发布并核对 `app/ui/` 与源文件的哈希一致。
